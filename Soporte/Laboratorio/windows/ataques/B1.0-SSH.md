`auto_ruido:canal-ssh`. **Nunca** sus hijos.

> **Candado de pertenencia (G-SSH.1).** Antes de `OPERADOR_WIN` y de `auto_ruido`, el filtro
> evalúa `es_del_ataque` (`win_cwd`/`win_command_line`/`win_target`/`syscheck_path` bajo
> `C:\lab-attack\ATA<NNN>`). Una fila con evidencia de ataque **nunca** cae en
> `ruido_conocido`/`auto_ruido`: o casa una detección declarada (`deteccion`), o es
> `artefacto_ataque` (lo dudoso sigue a `dudosa`). Así el predicado del canal no puede tapar
> una fila del ataque.

**Reglas duras respetadas:**

1. Si falta el campo que demuestra la condición (`logon_type`, usuario, IP) → **no se
   excluye** (cae a `deteccion`/`dudosa`; lado seguro).
2. Una señal de `deteccion` que declare una regla del predicado emite **`CONFLICTO`** y
   **prevalece la detección** (la detección va antes).
3. `--sin-operador` desactiva **solo** `OPERADOR_WIN` (no `auto_ruido`), para la sensibilidad.
4. El catálogo v1 **no cambia** (4 reglas); el canal es capa aparte.

> **Diferencia con el plan (declarada):** el plan proponía `67022/67023` por IP y `67028`
> por usuario. La evidencia añade `60106/60137/67024/67023` (SSH) y **quita la IP** (no
> existe). Se implementa lo medido; la regla por IP del plan se conserva **solo como
> declaración** (no demuestra nada). **El fallback `vmrun` no está listo**: su `4624/4634`
> real es tipo 4 con `srcip` vacío y `vmtoolsd.exe` no está en `auto_ruido` (política §9.6).

## 8. Desviaciones y lo que no cuadra

1. **La VM ya tenía OpenSSH Server** (Installed + Running) en `lab-listo-windows-ataques`.
   `construccion_resultado.md:4` dice “sin SSH”; se interpreta como “sin acceso configurado”,
   pero **la discrepancia se declara**. No se instaló nada; el payload offline no se usó.
2. **La IP del operador no es demostrable** en el `4624` de SSH (`Source Network Address: -`).
   El plan lo preveía como caso “sin IP” (§5.2); se aplica el predicado por usuario/regla.
   **CA-B1-18 se cumple con limitación declarada**; **R23** queda abierto hasta G-SSH.1.
3. **`win_user` del detalle normalizado es la cuenta *subject*** (equipo/SYSTEM) en
   `4624/4634/4688`; el usuario efectivo está en `targetUserName`. Se añade la columna
   **aditiva** `win_target_user` (además de las 4 del plan) para que el predicado sea
   demostrable **sin cambiar** las 23 columnas previas. El CSV del canal usa el usuario
   efectivo.
4. **El dry run con `cmd /c echo SSH-OK`** devuelve `SSH-OK"` (artefacto de quoting del
   cliente Git/Windows); con `echo SSH-OK` sale limpio. Se declara.
5. **Los `_tester_*` y `material` del snapshot previo se conservan** (no se borra contenido
   de la baseline); solo se limpiaron los ficheros temporales de esta tanda.
